# Агентур'a — AI-агент для ваших чатов

[English](README.md) | **Русский**

Агентур'a — AI-агент для чатов с памятью, навыками, настроением, чатовой файловой системой и задачами по расписанию. Он запускается на вашем сервере и работает через подключаемые адаптеры мессенджеров. В текущем виде реализован адаптер Telegram; архитектура предусматривает подключение других платформ.

У каждого чата своя память, настройки и интеграции. Вы выбираете LLM-провайдера, а данные агента хранятся в обычных файлах — отдельная база данных не нужна.

**Статус:** MVP, проект развивается. Текущие возможности и границы применения описаны в разделе [Ограничения](#ограничения).

| Настраивать расписание | Попросить о регулярном напоминании, ответе агента или запуске навыка, затем включить созданное задание. |

## Быстрый запуск через Docker

### 1. Подготовьте окружение

Понадобятся:

- Docker с командой `docker compose`;
- токен Telegram-бота от [@BotFather](https://t.me/BotFather);
- API-ключ и идентификатор модели у LLM-провайдера с совместимым Chat Completions API;
- исходящий доступ к Telegram и выбранному LLM API.

Для навыков, памяти по запросу и расписания выбирайте модель с поддержкой вызова инструментов (tool calling). Использование API оплачивается по условиям вашего провайдера; ключ указывает владелец бота.

Клонируйте этот репозиторий или скачайте ZIP, перейдите в каталог проекта и создайте конфигурацию:

```bash
cp .env.example .env
```

### 2. Заполните `.env`

Обязательны три значения:

```dotenv
TELEGRAM_BOT_TOKEN=ваш-токен-бота
LLM_API_KEY=ваш-api-ключ
LLM_MODEL=идентификатор-модели-у-провайдера
```

По умолчанию в примере указан `LLM_BASE_URL=https://api.openai.com/v1`. Для другого провайдера измените этот адрес — [варианты настройки](#настройки-и-llm-провайдеры).

`TELEGRAM_ALLOWED_CHAT_ID` ограничивает доступ одним или несколькими числовыми ID чатов через запятую. **Пустое значение разрешает работу во всех доступных боту чатах, включая личные.** Чтобы получить ID своего чата без стороннего бота, отправьте `/agentur help` после запуска и найдите `chatId: "telegram:…"` в логах. В `.env` укажите только числовую часть, сохраняя знак минус, если он есть, затем пересоздайте контейнер командой `docker compose up -d`.

### 3. Запустите бота

```bash
docker compose up -d --build
docker compose logs --tail=100 -f
```

При успешном старте в логах появится `Starting Agentur'a`. Данные сохраняются на хосте в `./data`, смонтированном в `/app/data`. Публиковать порт или настраивать входящий webhook не требуется.

### 4. Проверьте первый ответ

Откройте личный чат со своим ботом и отправьте:

```text
/agentur help
/agentur doctor
```

`help` показывает команды. `doctor` проверяет доступность каталога данных, Telegram, LLM и, если включено, вызов инструментов. Успешный результат содержит `telegram: ok`, `llm: ok` и `llm tools: ok`; сама проверка обращается к API провайдера.

Затем напишите обычное сообщение, например: «Привет! Чем ты можешь помочь?». В личном чате бот отвечает без упоминания. Для работы в группе выполните [настройку Telegram](#настройка-telegram).

## Настройка Telegram

1. Создайте бота в [@BotFather](https://t.me/BotFather) командой `/newbot` и сохраните токен в `.env`.
2. Добавьте бота в нужную группу; если задан `TELEGRAM_ALLOWED_CHAT_ID`, включите её ID в список.
3. Для чтения фоновой переписки, режима `smart` и произвольных команд навыков отключите privacy mode через `/setprivacy` → выберите бота → `Disable`. Если бот уже был в группе, удалите и добавьте его заново, чтобы настройка вступила в силу. См. [документацию Telegram](https://core.telegram.org/bots/features#privacy-mode).
4. Отправьте `@имя_вашего_бота Привет!` или ответьте на сообщение бота.

`TELEGRAM_BOT_USERNAME` можно оставить пустым: имя определяется автоматически при запуске. Для обычных ответов права администратора не нужны; право удалять сообщения используется при попытке удалить команду установки секрета.

## Настройки и LLM-провайдеры

Все настройки окружения собраны в [`.env.example`](.env.example). Бот использует Chat Completions API; совместимость конкретного endpoint и модели проверяется через `/agentur doctor`.

| Провайдер | `LLM_BASE_URL` | `LLM_MODEL` |
| --- | --- | --- |
| OpenRouter | `https://openrouter.ai/api/v1` | ID модели из каталога провайдера |
 OpenAI | `https://api.openai.com/v1` | ID доступной вам модели |
| Другой совместимый сервис | Адрес API вашего сервиса | ID модели этого сервиса |

`LLM_SUPPORTS_TOOLS=true` включает вызовы инструментов. Если endpoint их не поддерживает, установите `false`: обычные ответы останутся доступны, но модель не сможет выполнять действия через инструменты.

Основные параметры после копирования `.env.example`:

| Переменная | Значение в примере | Назначение |
| --- | --- | --- |
| `TELEGRAM_ALLOWED_CHAT_ID` | Пусто | Разрешённые чаты; один ID или список через запятую |
| `AGENT_TIMEZONE` | `Europe/Moscow` | Часовой пояс агента и создаваемых заданий, в формате IANA |
| `AGENT_DEFAULT_LOCALE` | `ru` | Язык новых чатов: `ru` или `en` |
| `AGENT_MAX_TOOL_STEPS` | `15` | Максимум шагов вызова инструментов за один ответ |
| `CONTEXT_WINDOW_TOKENS` | `32000` | Окно контекста; задайте в соответствии с моделью |
| `CONTEXT_BUDGET_TOKENS` | `12000` | Рабочий бюджет входного контекста |
| `REPLY_MAX_TOKENS` | `900` | Резерв и лимит генерации ответа |
| `LLM_TIMEOUT_MS` | `45000` | Таймаут запроса к LLM |
| `TELEGRAM_IMAGE_MAX_BYTES` | `5242880` | Лимит загружаемой фотографии: 5 МиБ |
| `TELEGRAM_ATTACHMENT_MAX_BYTES` | `5242880` | Лимит загружаемого документа: 5 МиБ |
| `SKILL_HTTP_ALLOWED_ORIGINS` | Пусто | Разрешённые HTTP origins; пусто отключает HTTP-инструмент и HTTP-запросы навыков |
| `MCP_ENABLED` | `false` | Подключение инструментов удалённых MCP-серверов |

Это значения **файла-примера**, а не все встроенные значения по умолчанию. Если переменные вообще не заданы, применяются значения из [`src/config.ts`](src/config.ts), некоторые из них отличаются. После изменения `.env` выполните `docker compose up -d`, чтобы контейнер получил новое окружение.

Настройки HTTP, секретов и MCP описаны в [руководстве по интеграциям](docs/ru/integrations.md).

## Общение и команды

В личном чате пишите обычным текстом. В группе используйте `@username` бота или ответ на его сообщение. Простое обращение по имени без `@` не является отдельным триггером.

`/agentur` — префикс команд управления. Например, `/agentur help` показывает справку; произвольный запрос после `/agentur` не передаётся модели как вопрос.

### Режимы ответа

- **`called`** — по умолчанию. В группе бот отвечает на упоминание, reply на своё сообщение и команды, включая команды включённых навыков.
- **`smart`** — бот также сохраняет фоновую переписку и обращается к LLM, чтобы решить, стоит ли вступить в разговор. Это может расходовать API даже без ответа в чат.

```text
/agentur reply-mode called
/agentur reply-mode smart
```

Задания по расписанию работают независимо от режима ответа. Режим `called` не запрещает сохранение фоновой переписки, если отдельно включён full capture — подробнее в разделе [Данные и доступ](#данные-и-доступ).

### Основные команды

| Команда | Действие |
| --- | --- |
| `/agentur help` | Справка по командам |
| `/agentur status` | Режимы и настройки чата |
| `/agentur doctor` | Проверка подключений и окружения |
| `/agentur language ru` или `en` | Язык чата |
| `/agentur reply-mode called` или `smart` | Режим ответа |
| `/agentur censor-mode on` или `off` | Предпочтение по использованию ненормативной лексики в ответах; не модерация участников |
| `/agentur identity` | Текущий характер и правила агента |
| `/agentur identity set <текст>` | Сохранить характер и правила |
| `/agentur identity reset` | Сбросить их |
| `/agentur mood` / `/agentur mood reset` | Посмотреть / сбросить оценку атмосферы чата |
| `/agentur facts` | Сохранённые факты |
| `/agentur decisions` | Сохранённые решения |

## Характер бота для каждого чата

Боту можно задать свой характер, тон общения и правила через **identity**. Один и тот же бот может быть лаконичным помощником в рабочем чате и более свободным собеседником с чувством юмора в компании друзей. В каждом чате сохраняется своя identity.

Например, для рабочего чата:

```text
/agentur identity set Ты помощник нашей команды. Отвечай коротко и понятно, помогай следить за принятыми решениями и задавай вопросы, если что-то неясно.
```

Для identity также можно отправить UTF-8 файл `.txt` или `.md` с подписью `/agentur identity set`.

## Навыки и расписание

### Навыки

Навык — программа для повторяемой задачи конкретного чата. Опишите задачу агенту, например: «Создай навык для списка покупок: добавлять товары, показывать и очищать список». Для создания навыков модель должна поддерживать tool calling.

Новый навык сохраняется выключенным. Посмотреть и включить его можно так:

```text
/agentur skills
/agentur skill enable <id>
/agentur skill disable <id>
/agentur skill delete <id>
```

При включении выполняются проверка кода и пробный запуск. Агент выбирает включённые навыки по их описанию; отдельная slash-команда нужна только для явно настроенного command trigger.

Навыки хранятся в `skills/custom/<id>/` внутри каталога чата. При обновлении сохраняется одна предыдущая редакция для отката. **Обновление уже включённого навыка сохраняет его включённое состояние**; повторное включение не требуется. Перезапуск приложения для изменений навыков не нужен.

Код навыков исполняется в QuickJS, с доступом к памяти, спискам, файлам и разрешённым интеграциям через SDK. Контракт, примеры и ограничения — в [руководстве по навыкам](docs/ru/skill-packages.md).

### Задания по расписанию

Попросите агента создать регулярное задание, например: «Каждый будний день в 10:00 напоминай о планёрке». Он может создать задание на отправку текста, запрос к модели или запуск инструмента навыка.

```text
/agentur cron list
/agentur cron enable <id>
/agentur cron disable <id>
/agentur cron delete <id>
```

Новые задания выключены до включения. У каждого задания свой часовой пояс; если он не указан при создании, используется `AGENT_TIMEZONE`. Для выполнения расписания процесс бота должен работать. При запуске инструмента навыка по расписанию навык должен быть включён; его command triggers не проверяются.

## Данные и доступ

### Что хранится

В Docker каталог `./data` на хосте соответствует `/app/data` внутри контейнера. При стандартном запуске данные чата лежат в `data/chats/<encoded-chat-id>/`. Имя папки — base64url от строки `telegram:<числовой-ID>`.

| Путь внутри каталога чата | Содержимое |
| --- | --- |
| `chat/recent.jsonl` | Буфер сообщений, авторы и ссылки на вложения |
| `chat/summary.md`, `chat/interaction-summaries.jsonl` | Накопленный контекст и сводки взаимодействий |
| `chat/facts.json`, `chat/decisions.json` | Факты и решения |
| `chat/identity.md`, `chat/settings.json` | Характер, язык и режимы чата |
| `chat/mood.json`, `chat/mood-history.jsonl` | Оценка атмосферы чата |
| `chat/secrets.json` | Ключи интеграций в открытом виде |
| `chat/lists/` | Списки навыков |
| `skills/custom/`, `skills/state/`, `skills/audit/` | Навыки, их состояние и журнал запусков |
| `attachments/`, `artifacts/` | Полученные вложения и созданные файлы |
| `integrations/mcp/` | Настройки MCP-серверов и журнал обращений |
| `cron/jobs.json` | Задания расписания |

### Какая переписка попадает в контекст

- В `called` без full capture сохраняются обращения к боту, команды, сообщения, запускающие навыки, и ответы бота.
- В `smart` сохраняются также фоновые сообщения; часть недавней переписки передаётся модели для решения об ответе.
- `TELEGRAM_FULL_CAPTURE_CHAT_IDS` включает сохранение всех обрабатываемых сообщений выбранных чатов независимо от режима ответа. Укажите числовые ID через запятую или `*` для всех чатов. Это не загрузка старой истории Telegram.

Буфер сообщений сокращается по мере накопления; часть контекста остаётся в сводках. Вложения и другие файлы имеют отдельное хранение, поэтому лимит буфера не ограничивает размер всего `data/`.

При обращении к LLM выбранному провайдеру передаются запрос и собранный контекст: история, память, инструкции, изображения при их использовании и результаты инструментов. HTTP- и MCP-интеграции передают данные соответствующим сервисам. Локальное хранение файлов не означает, что обработка происходит целиком на вашем сервере.

### Кто может управлять ботом

Ограничение доступа задаётся на уровне чатов. В текущей версии команды управления внутри разрешённого чата не проверяют роль администратора или владельца: участники могут менять настройки, навыки, расписание и интеграции. Память разделена между чатами, но общая для участников одного чата и его тем.

Секреты хранятся без шифрования. Команда `/agentur secret set` проходит через историю сообщений; попытка удалить её из Telegram не очищает локальную историю. Подробнее о текущем поведении — в [разделе о секретах](docs/ru/integrations.md#секреты).

## Обслуживание

```bash
# Посмотреть состояние и последние логи
docker compose ps
docker compose logs --tail=100

# Остановить приложение; каталог ./data останется на хосте
docker compose down

# Собрать и запустить после обновления исходников
docker compose up -d --build
```

Перед обновлением остановите бота и сохраните копию `data/` и `.env` в закрытом месте. Для восстановления верните файлы при остановленном приложении и запустите совместимую версию кода. Одновременный запуск нескольких экземпляров с одним Telegram-токеном или общим каталогом данных не предусмотрен.

Для удаления данных отдельного чата остановите бота и удалите соответствующий каталог `data/chats/<encoded-chat-id>/`. При следующем обращении он будет создан заново. Удаление локальных файлов не удаляет сообщения из Telegram и данные, уже переданные внешним сервисам.

В поставляемом Compose оставьте `AGENT_DATA_DIR=./data` или укажите `/app/data`: оба пути ведут к смонтированному каталогу. Для другого пути нужно также изменить монтирование в `docker-compose.yml`.

## Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| Контейнер завершается при старте | `docker compose logs --tail=100`: заполнены ли обязательные переменные, корректны ли токен, URL API и часовой пояс |
| Бот отвечает в личном чате, но молчит в группе | ID группы в allowlist, упоминание `@username`, privacy mode и право отправлять сообщения |
| После `/agentur <вопрос>` появляется справка | Это команда управления. Задайте вопрос обычным текстом в личном чате или через `@username` в группе |
| `help` работает, а обычные ответы — нет | `/agentur doctor`: ключ LLM, доступность модели, баланс, адрес API и доступ к сети |
| Ответы есть, но агент не выполняет действия | `LLM_SUPPORTS_TOOLS`, поддержка tools моделью, результат `llm tools` в диагностике |
| Навык не обращается к API | Origin разрешён в `.env` и в manifest навыка, нужные секреты заданы; [настройка HTTP](docs/ru/integrations.md#http) |
| MCP недоступен | `MCP_ENABLED=true`, адрес сервера, Bearer-токен и ограничения tools/resources; [настройка MCP](docs/ru/integrations.md#mcp) |
| Расписание не срабатывает | Задание включено, его часовой пояс верен, бот запущен, требуемый навык включён |
| После изменения `.env` ничего не изменилось | Выполните `docker compose up -d`; простой restart не подхватывает новое окружение контейнера |

## Разработка

Проект написан на TypeScript. В `package.json` указано требование Node.js `>=20`; Dockerfile использует Node.js 20.

Для локального запуска установите Node.js и npm, подготовьте `.env`, как в быстром старте, затем выполните:

```bash
npm ci
npm run build
npm start
```

Для запуска исходников используйте `npm run dev`. Проверки: `npm run lint`, `npm test`, `npm run build`. `npm run format` форматирует файлы и изменяет их на диске.

Проверки можно выполнить в Docker, не устанавливая зависимости на хост:

```bash
docker build --target build -t agentur-check .
docker run --rm --network none agentur-check npm run lint
docker run --rm --network none agentur-check npm test
```

Этап `build` уже выполняет TypeScript-сборку. Для этих проверок не нужно передавать контейнеру `.env` или подключать рабочий `data/`.

## Ограничения

- Telegram — текущий интерфейс; используется long polling, без webhook и веб-панели.
- Файловое хранение без БД. Работа нескольких процессов с общим data/ не проверена в production и требует отдельной валидации механизмов синхронизации записи, восстановления после сбоев и сценариев масштабирования.
- Качество ответов, вызовов инструментов и анализа изображений зависит от модели и провайдера. Совместимый URL сам по себе не гарантирует поддержку всех возможностей.
